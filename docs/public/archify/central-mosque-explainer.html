How is the Central Mosque of Bogotá platform architected and verified?

Long image

A

Answer

The platform pairs an offline-resilient Astro 7 SSR frontend on port 4321 with a Strapi v5 Headless CMS on port 1337 across four locales (es, en, ar, tr).

  1. Ten Astro Content Layer loaders fetch Strapi v5 REST collections and fall back to deterministic 4-locale mocks when Strapi is unreachable.
  2. Server-only BFF endpoints validate contact, visit, service-desk, and donation payloads with Zod before forwarding to Strapi.
  3. Ten custom @vicacha-strapi/* plugins provide Tiptap rich text, QR generation, prayer CSV import, and editorial dashboards.
  4. A single TypeScript runner (scripts/verify-all.ts) enforces formatting, lint, types, 98% unit test coverage, Storybook build, and Starlight docs limits.

  1. Community Visitor ↗

    Requests localized routes in Spanish, English, Arabic RTL, or Turkish.

  2. Astro 7 SSR Server ↗

    Renders localized pages using Starwind UI and Tailwind CSS 4 logical properties.

  3. Content & API Loaders ↗

    Queries Strapi v5 first and falls back to 4-locale mock fixtures on network error.

  4. BFF API Endpoints ↗

    Validates form submissions with Zod and keeps STRAPI_API_TOKEN on the server.

  5. Strapi v5 CMS ↗

    Manages 17 Content-Types and 10 custom @vicacha-strapi/* editorial plugins.
